# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                      # Run the server (node server.js)
npm run prisma:migrate         # Run DB migrations (prisma migrate dev --name init)
npm run prisma:generate        # Regenerate Prisma client after schema changes
npm run generate:static-seo    # Rebuild state/city/service SEO pages
```

There is no build step, no test suite, and no lint command — this is a plain Node.js app.

## Architecture

**Stack**: Node.js + Express + PostgreSQL (Prisma ORM) + vanilla JS frontend. No React, no bundler, no framework.

**Entry point**: `server.js` (~5,500 lines) — a monolith containing all Express routes, middleware, business logic, auth, and service integrations. There is no separate route or controller layer.

**Frontend**: Static HTML files served by Express, with vanilla JS scripts (no SPA framework). Key scripts: `script.js` (map/search/lead capture), `abel-chat.js` (AI chat widget), `search-results.js`, `analytics-tracker.js`.

**Database**: PostgreSQL via Prisma. Schema is in `prisma/schema.prisma`. Models: `Provider`, `Lead`, `LeadNotification`, `LeadOutcome`, `LeadOutcomeEvent`, `ProviderUser`, `ProviderUserProvider`, `NotificationJob`, `ProviderImpression`, `RateLimitEvent`, `BlogPost`, `BlogComment`, `BlogEmailVerification`, `AdminAuditLog`.

**SEO pages**: State and city landing pages live in `/states/` (static HTML). These are generated by `scripts/generate-static-seo-pages.js` and must be regenerated when provider data or templates change. Multiple sitemaps are served dynamically.

## Core Data Flow

1. User enters ZIP → Geocode via Nominatim → Center Leaflet map → Query Overpass API for hospice facilities nearby
2. Merge OSM results with provider DB + featured defaults → Display sorted provider results
3. Guided questionnaire collects care preferences + email → Creates `Lead` record
4. `NotificationJob` queue dispatches provider alerts (email via SendGrid, SMS via Twilio) with tier-based delay: priority=0ms, featured=60s, verified=120s
5. Providers view leads in dashboard, update status (`new` → `contacted` → `qualified` → `admitted`/`not_a_fit`/`no_response`)

## Auth System

Three separate auth contexts — all implemented in `server.js`:

- **Admin**: Token-based (`x-admin-token` header) with 4 tokens (`ADMIN_TOKEN_ADD/REMOVE/DASH/AUDIT`), or session cookie (`bh_admin_session_v2`) via email+password JWT login
- **Provider**: JWT in `Authorization: Bearer` header; stored in `localStorage` on client. Supports multi-provider accounts (one user → many providers via `ProviderUserProvider`)
- **Blog authors**: Email verification codes via `BlogEmailVerification`

## Feature Flags (env-based)

Services gracefully degrade when env vars are absent:
- Email (SendGrid): disabled if `SENDGRID_API_KEY` missing
- SMS (Twilio): disabled if `TWILIO_ACCOUNT_SID`/`TWILIO_AUTH_TOKEN`/`TWILIO_FROM_NUMBER` missing
- Payments (Stripe): disabled if `STRIPE_SECRET_KEY` missing
- AI chat (Abel/Anthropic): disabled if `ANTHROPIC_API_KEY` missing
- Captcha (Cloudflare Turnstile): bypassable with `TURNSTILE_BYPASS=true`

## Rate Limiting

Custom rate limiting using `RateLimitEvent` table (hashed IPs):
- Lead submission: 5 per 2-hour window
- Auth attempts: 10 per hour
- Abel chat: 20 messages per hour per IP
- Admin login: 5 failures per hour
- Bypass via `AUTH_RATE_LIMIT_BYPASS_IPS` (comma-separated IPs)

## Key Env Vars

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `ADMIN_TOKEN_ADD/REMOVE/DASH/AUDIT` | Admin API tokens |
| `ADMIN_LOGIN_EMAIL` / `ADMIN_PASSWORD_HASH` | Admin dashboard login |
| `ADMIN_SESSION_SECRET` / `PROVIDER_JWT_SECRET` | JWT signing secrets |
| `SENDGRID_API_KEY` / `SENDGRID_FROM_EMAIL` | Email notifications |
| `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` / `TWILIO_FROM_NUMBER` | SMS |
| `STRIPE_SECRET_KEY` / `STRIPE_PRICE_ID` / `STRIPE_WEBHOOK_SECRET` | Payments |
| `ANTHROPIC_API_KEY` | Abel AI chat |
| `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | Cloudflare Captcha |
| `IP_SALT` | Salt for IP hashing in rate limits |
| `CANONICAL_DOMAIN` | Used in sitemaps and canonical tags |
| `COOKIE_DOMAIN` | Admin session cookie domain (`.besthospice.com` in prod) |

## Provider Plan Tiers

Normalized values: `verified`, `featured`, `priority`. Controls notification delay, search ranking, and badge display. Managed via Stripe subscriptions or admin CRUD.

## Startup Side Effect

On server start, `fixTusconProviderData()` runs to correct "Tuscon" → "Tucson" spelling in the DB. Safe to run repeatedly.
